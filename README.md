# @armikom/api-client

TypeScript client for the Armikom API. Generated from the **frozen v1 contract**
(`api-v1.2` on `Armikom.Api`: `info.version` `v1`), plus the hand-written core runtime that
[`01-sdk-specification.md`](https://github.com/alarmsdk/Armikom.Api/blob/master/docs/frontend/01-sdk-specification.md)
requires.

Apache-2.0. Node ≥ 20. Dual ESM/CJS. **No runtime dependencies.**

## The three layers

```
┌──────────────────────────────────────────────────────────────────────┐
│ 3. src/armikom/   ergonomics — ArmikomClient, reference cache, SSE    │  hand-written
├──────────────────────────────────────────────────────────────────────┤
│ 2. src/core/      the core runtime — THE SPEC LIVES HERE              │  hand-written
│    auth · errors · retry · paging · cache · files · i18n · SSE       │
├──────────────────────────────────────────────────────────────────────┤
│ 1. generated/     transport — models + one function per operationId   │  generated
└──────────────────────────────────────────────────────────────────────┘
```

**Layer 2 knows nothing about the Armikom API.** That is the point: it is also what the
Voice.Cloud console runs on, and what an Angular or React app binds to. Import it on its
own when you are talking to a different Armikom service:

```ts
import { HttpClient, AuthSession, describeError } from '@armikom/api-client/core';
```

Layer 1 is regenerated by `make generate` and **never hand-edited** (§01 L-1). Layer 3 adds
sugar, never behaviour (§01 L-4).

## Quick start

```ts
import { ArmikomClient, WebStorageTokenStore } from '@armikom/api-client';
import { AlarmEventsApi, SidesApi } from '@armikom/api-client/generated';

const client = new ArmikomClient({
  baseUrl: 'https://api.armikom.net',
  // §01 A-11 — persistence is the host application's decision, made explicitly.
  tokenStore: new WebStorageTokenStore(localStorage),
  culture: 'tr',
  timeZone: 'Europe/Istanbul',
  userAgent: 'armikom-web/1.4.2',
});

await client.session.login({ email, password });

// Capabilities, not roles (§01 A-9). Exact match: sides:write does not imply sides:read.
if (client.session.can('alarms:read')) {
  const alarms = await client.api(AlarmEventsApi).getAlarmEvents({});
}

// Reference data: cached, ETag-revalidated, and indexed (§01 CA-3/CA-4).
const reference = await client.reference.indexed();
reference.signalType(row.signalTypeId)?.name;

// Realtime, with a coalesced re-read per burst and a resync on every reconnect.
client.stream.start();
client.stream.onAlarmListChanged(() => void reloadQueue());
client.stream.onResync(() => void reloadQueue());

// And the fallback that must announce itself (§01 S-10).
const feed = client.pollingFallback(() => void reloadQueue());
feed.start();
feed.mode.subscribe((mode) => showBadge(mode)); // 'live' | 'polling'
```

Errors are typed and branch on `code`, never on a string match:

```ts
import { ConflictError, describeError } from '@armikom/api-client/core';

try {
  await client.api(AlarmEventsApi).lockAlarmEvent({ id });
} catch (error) {
  if (error instanceof ConflictError && error.code === 'ALARM.LOCKED_BY_OTHER_USER') {
    offerForceTake(error.params?.lockedByUserName);
  } else {
    const { message, correlationId, kind } = describeError(error, { t: i18n.t });
    toast(kind, `${message} (${correlationId})`);
  }
}
```

## What layer 2 gives you

| Area | §01 | What it does |
|---|---|---|
| `session.ts` | §3 | Proactive refresh 60 s before expiry, single-flight, replay-once on 401, terminal codes end the session, `can()` / `canAll()` |
| `errors.ts` | §4 | `ProblemDetails` **and** the flat `{ error }` envelope → one class hierarchy carrying `code`, `params`, `correlationId` |
| `http-client.ts` | §3–6, §14 | Headers, auth, retry, per-call deadline, cancellation, offline refusal |
| `retry.ts` | §6 | Backoff with full jitter, `Retry-After`, and **no POST retry** |
| `paging.ts` | §10 | Four wire shapes → one `Page<T>`, one iterator, `isCapped` for the truncating endpoints |
| `resource.ts` | — | The loading/error/data triple and a paged list's whole state, written once |
| `cache.ts` | §7 | ETag revalidation, persistent store, indexed reference lookups |
| `files.ts` | §11 | Object URLs that are actually revoked, upload progress, streamed downloads |
| `i18n.ts` | §9 | Fallback chain, `{{param}}` interpolation, **missing keys are observable** |
| `text.ts` | §5, §9 | Labels the API's offset-less timestamps as the UTC they are; strict instant parsing; Turkish-safe casing |
| `realtime.ts` | §12 | SSE over `fetch` (so it can hold a bearer header), reconnect, keep-alive watchdog, `resync` on every open, nudge coalescing, polling fallback |
| `logger.ts` / `telemetry.ts` | §13 | Structured events, redaction, batched best-effort shipping |
| `connectivity.ts` | §14 | online / degraded / offline from real outcomes, not `navigator.onLine` |

`observable.ts` carries the one reactive primitive: a `Store` with `get()` +
`subscribe(listener)`, readable by **Angular** (`toSignal(from(store))`, via the
`Symbol.observable` interop) and by **React** (`useSyncExternalStore(store.subscribe,
store.get)`) with no adapter package and no framework dependency. See
[`examples/angular`](examples/angular) and [`examples/react`](examples/react).

## Layout

```
openapi/     pinned spec + its recorded sha256, and the generator config
generated/   layer 1 — produced by `make generate`, NEVER hand-edited, committed
src/core/    layer 2 — the core runtime; framework-free and API-agnostic
src/armikom/ layer 3 — the composition root and the Armikom-specific bindings
checks/      contract checks (generated layer) + the conformance matrix (core)
examples/    ready-to-copy Angular and React bindings
docs/        design notes
```

## Commands

| | |
|---|---|
| `make verify-spec` | the pinned spec still matches its recorded sha256 |
| `make generate` | regenerate `generated/` (deterministic; refuses on hash mismatch) |
| `make build` | dual ESM/CJS build under `tsc --strict` |
| `make test` | contract checks **and** the core conformance matrix (runs under `TZ=Europe/Istanbul` — see below) |
| `make check-drift` | regenerate and fail on any diff under `generated/` |

Generation needs **Java 21** (openapi-generator is a JVM tool) and network access on first run to
fetch the pinned generator jar. `make build` and `make test` need neither.

## Conformance

`checks/core/` implements the matrix from
[`02-sdk-codegen-and-packaging.md`](https://github.com/alarmsdk/Armikom.Api/blob/master/docs/frontend/02-sdk-codegen-and-packaging.md) §5.1.
Each test names its id, so a failure says which rule broke:

| | | | |
|---|---|---|---|
| C-01 injectable clock | C-02 proactive refresh | C-03 single-flight refresh | C-04 terminal auth errors |
| C-05 no secrets in logs | C-06 full ProblemDetails | C-07 generated error codes | C-08 non-JSON error body |
| C-09 UTC parsing | C-11 no POST retry | C-12 global deadline | C-13 ETag revalidate |
| C-14 Turkish casing | C-15 unified pagination | C-16 object-URL revocation | C-17 nudge coalescing |
| C-18 tolerant pbx payload | C-19 resync on reconnect | C-20 unknown-field tolerance | C-21 stream 403 is terminal |
| C-22 keep-alive watchdog | C-23 honour `Retry-After` | C-24 capped array | C-25 no-op is not an error |

C-10 (patch tri-state) is a codegen concern rather than a runtime one and is checked in
`checks/contract/`.

## What is pinned, and why it is pinned twice

- **`openapi/armikom-api.v1.json`** is copied from the frozen artifact on `Armikom.Api`.
  Its sha256 is recorded in `openapi/armikom-api.v1.json.sha256` and enforced by `make verify-spec`.
- **openapi-generator `7.24.0`** is pinned exactly (never `latest`) in `Makefile`, `openapitools.json`
  and `package.json`. Bumping it rewrites `generated/` and CI will fail until the result is committed.

CI checks both halves independently (`.github/workflows/contract.yml`): the *drift* job catches a
hand-edit of generated code, the *pin* job catches this repo drifting off the frozen contract.

## Contract decisions the generated layer must honour

- **D69** — all 27 `GET` lists under `/v1/reference/` return **bare arrays**, not a paged envelope.
- **D70** — `DeleteOperatorUser`, `GetRole`, `GetSideControl`, `GetSideSimCard`, `GetSideMail` are
  deliberately absent. They are not gaps; do not stub them.
- **D71** — `info.version` is `v1`; this package is `1.x`.
- **D72** — path parameter names drive generated method-group names.

`checks/contract/` asserts all four, at the type level and at runtime.

## Timestamps

§01 R-4: every wire timestamp is UTC ISO-8601 and must parse to an **absolute instant**.
`typescript-fetch` deserialises with `new Date(...)`, which reads an offset-less string in the *host*
zone. The check suite therefore runs under `TZ=Europe/Istanbul`, not UTC — under UTC that leniency is
invisible.

**The API sends offset-less timestamps.** Verified against a live instance on 2026-08-20 by the Vue
console: every value sampled came back as `"2026-08-20T19:09:48.991674"`. Under `Europe/Istanbul`
that reads three hours early, and every alarm age, lock age and countdown in a console is wrong by
the host offset — silently, because CI runs in UTC where the shift is zero.

So the pipeline **labels** them rather than merely refusing them: `markTimestampsUtc` walks each JSON
response body before the generated `FromJSON` sees it, which is the only point where the original
text still exists. It is idempotent — a value already carrying `Z` or an offset does not match — and
it can be turned off with `repairTimestamps: false`. `parseInstant` stays strict by default for
values arriving by any other route; pass `{ assumeUtc: true }` to accept one.

## Consumers

- **`armikom-web`** (planned) — the operator console, on layers 1–3.
- **`Armikom.Voice.Cloud/console`** — the Voice.Cloud console, on **layer 2 only**: it
  talks to the control plane, which is a different API. It currently vendors `src/core`
  (see that repo's `scripts/sync-sdk.sh`) because the package is not yet published to a
  registry its Docker build can authenticate against. Publishing turns that into a
  `npm i` and an import rewrite.
